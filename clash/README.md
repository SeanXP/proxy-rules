# Clash

这是一份供家庭 OpenClash 使用的 Subconverter 外部配置。它只定义规则集、策略组和节点分组方式，不保存订阅、节点或 OpenClash 的运行参数；当前行为以 [`clash.ini`](./clash.ini) 为准。

## 目标与定位

这份配置是家庭局域网的兜底代理，不是个人设备上的全功能代理配置。设计目标按优先级排列如下：

1. 稳定：尽量减少远程规则、策略组、DNS 干预和自动化逻辑。
2. 清晰：只有明确需要代理的流量才进入代理策略，其他流量默认直连。
3. 低维护：地区和业务策略只覆盖当前实际需求，不预先支持假设场景。
4. 可控：AI、流媒体和 Crypto 等有明确地区要求的服务保留独立路径。

在 Rule 模式下，未命中规则的流量由 `FINAL -> DIRECT` 直连。需要临时让全部流量走代理时，应在 OpenClash 中切换到 Global 模式，而不是修改日常的 FINAL 策略。

Clash 与 Shadowrocket 只统一 `SELECT / AI / Media` 等策略语义、地区名称和测速口径，不追求功能逐项一致。同名的 `VPS` 组内容不同：Clash 包含全部 vps 节点，作为 SELECT 的手动兜底；Shadowrocket 只包含美国出口的 vps 节点，仅供 AI 使用。Shadowrocket 是个人移动端配置；OpenClash 位于家庭网络入口，误分流或代理故障会影响所有家庭成员，因此默认路径更保守。

## 当前流量路径

规则按顺序匹配，命中后不再继续：

| 顺序 | 流量 | 策略 | 目的 |
| --- | --- | --- | --- |
| 1 | 局域网和私有网络 | `DIRECT` | 保证家庭内部访问不进入代理。 |
| 2 | 明确的直连例外 | `DIRECT` | 避免被后续代理规则误匹配。 |
| 3 | OpenAI 和 AI 补充规则（含 Claude） | `AI` | 使用适合 AI 服务的出口。 |
| 4 | Crypto | `SG` | 使用固定地区，不增加中转策略组。 |
| 5 | Apple | `DIRECT` | 优先于 Media 和 Global 处理重叠域名。 |
| 6 | GlobalMedia（含 Netflix 域名） | `Media` | 独立选择流媒体出口。 |
| 7 | Global | `SELECT` | 代理明确的国外通用流量。 |
| 8 | 其他未命中流量 | `DIRECT` | 家庭网络默认兜底。 |

## 当前策略职责

- `SELECT`：通用代理入口，第一选项为机场 HK，也可以手动切换到其他地区、VPS 或 DIRECT；VPS 只作为手动兜底，不做自动故障转移。
- `AI`：AI 服务入口，先列出名称包含 `vps` 且带独立 `us`/`usa` 字样的美国出口自建节点（如 `vps-us`、`vps-hk-us`），之后是机场 US。
- `Media`：流媒体入口，可以跟随 SELECT，也可以指定地区或 DIRECT。
- `VPS`：名称带有 `vps` 的全部自建节点，作为 SELECT 的手动兜底。
- `HK`、`US`：排除名称中带有 `vps` 的节点，只在对应机场节点之间自动测速；`US` 只匹配独立的 `US`/`USA` 字样，避免误匹配 `AUS`、`RUS`、`USDT` 等。
- `SG`、`JP`：按地区过滤节点并自动测速；所有地区组使用相同的检测地址和测速参数（`https://www.gstatic.com/generate_204`，间隔 600 秒、超时 5 秒、容差 50 ms）。

## 设计与维护约束

后续修改遵循以下规则：

1. **默认保持直连兜底。** 家庭 Rule 模式使用 `FINAL -> DIRECT`；全量代理通过 OpenClash Global 模式临时启用。
2. **只为不同的最终行为创建策略组。** 固定走 DIRECT、SG 等明确出口的规则直接指向最终策略，不增加只做一次转发的中间组。
3. **保持业务组最小化。** 默认只保留 `SELECT / AI / Media`；新增业务组必须存在长期、独立的手动选路需求。
4. **地区组按实际需求创建。** 默认只保留 `HK / SG / JP / US`，不建立全部节点、其他地区或没有真实需求的地区组。
5. **地区正则宁可漏匹配，不要误匹配。** 只使用完整国家或地区名称、ISO 代码、常见英文名或旗帜；不枚举城市、机场前缀或容易误匹配的单字。HK 和 US 必须排除带有 `vps` 的自建节点，自建节点只通过 `VPS` 组或业务组中的明确 vps 正则使用。subconverter 正则区分大小写，自建节点统一用小写 `vps-<地区>[-<出口地区>]` 命名，出口地区放最后。遇到真实漏匹配后再补一个明确关键词。
6. **家庭网关不承担附加过滤功能。** 默认不加入广告过滤、HTTPDNS 拦截或复杂 DNS 干预；只有出现可复现问题，并确认应由 OpenClash 解决时才增加。
7. **默认直连时不维护重复国内规则。** 在 `FINAL -> DIRECT` 不变的前提下，不额外加入 China、GEOIP CN 等大范围国内规则。
8. **按行为等价判断规则冗余。** 只有当规则被更早或等价的规则覆盖，并且最终策略相同时才能删除；不能仅凭文件名、服务名或部分域名重叠判断。
9. **Google 系服务保持同一出口。** Gemini 不单独分流，随 Global 走 `SELECT`；若 Gemini 与其他 Google 域名出口不同，Google 会提示 IP 不一致。
10. **保持规则优先级。** 总体顺序为 `Lan -> Direct -> AI/Crypto -> Apple -> Media -> Global -> FINAL`；Apple 必须早于 Media 和 Global，FINAL 必须位于最后。
11. **先验证问题，再扩大配置。** 偶发访问失败不自动意味着需要新增规则、策略组或地区。
12. **区分静态检查和运行验证。** 修改后检查策略引用、空节点组、远程 URL 和生成结果；静态检查通过不代表配置已经在 OpenClash 中加载并正常运行。

如果一项改动不能明确回答“什么流量、为什么需要、最终走哪里”，通常就不应该加入这份家庭兜底配置。
